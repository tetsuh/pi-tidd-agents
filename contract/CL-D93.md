## CL-D93 — A packaged driver sequences the review; the parent only makes the calls it prints
**Clauses:** CL-D93-driver, CL-D93-phases, CL-D93-readiness-scope, CL-D93-record, CL-D93-tests

*Decision ID:* CL-D93
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#196` at its body and the owner choice https://github.com/tetsuh/pi-tidd-agents/issues/196#issuecomment-5870929892 (working session of 2026-09-28)
*Question:* Parents composing helper requests from prose lost whole runs to shape errors (#194 records eight on one consumer PR), and each CL-D56-class fix removed one composed document at a time. The #191 spike drove about 130 review-only operations and one exact-autofix run to `MERGE_READY` with no orchestration failure (milestone #155). Does the package ship that driver, and on what boundary?
*Options and trade-offs:* Packaging the driver crosses CL-D37's "no package entrypoint" boundary for one directory and makes the prose a specification the driver implements rather than a procedure the parent follows. Leaving it outside keeps the boundary and leaves every consumer's parent composing requests.
*Recommendation:* Package it, under its own alarms.
*Owner choice:* Package it (https://github.com/tetsuh/pi-tidd-agents/issues/196#issuecomment-5870929892). `skills/closed-loop-pr/driver/` holds `run.js`, `readiness.js` (the external half of readiness, split from `run.js` under the per-file alarm), `phases.js` (the phases of a review-only round, which `review.js` calls and a later driver can share), and `review.js`, invoked by the parent as `node <package>/skills/closed-loop-pr/driver/review.js`; they are not a `bin`, `main`, `exports`, or extension. Every helper operation goes through the package's own `helpers/cli.js`, every fingerprint and evidence record included, so each request is normalized and shape-checked as any caller's would be and no fingerprint a helper defines is computed beside the helpers. The commits the `pr_commits` fingerprint reads are framed by NUL, which Git never stores in a message, so each message is its own bytes. The helpers define no pull-request body fingerprint, so this record defines it: the `github:pr:<number>:body` identity is the SHA-256 of the body's LF-normalized UTF-8 bytes, computed by the driver and re-read before every later gate. The driver alarms are 30,000 bytes per file and 60,000 in aggregate, separate from the helper alarms. `contractInput` is the SHA-256 of the package's own authority files the gate reads, each prefixed by its path, in the driver's stated order. Validation commands come from `.tidd.json` at the base commit (`{"validate": [[argv…], …]}`), so the change under review cannot choose them; a missing or malformed file, or an Issue with no `Acceptance criteria` bullet, stops `BLOCKED` before any gate. CL-D97 later let a missing base file fall back to `--validate` or the operator's own configuration, and review-only proceed with none. The run directory, or the temporary root a default one is created under, is refused before anything is created when it resolves inside a Git work tree, and every later command that opens the run (`result`, `resume`, `status`) judges it the same way before it takes the lock, and a given one must be absent or an empty real directory that the operator owns and no one else can write; the publication artifacts are written inside it, and every run artifact is written without following a link at its path; every gate after the first, and final readiness, re-resolves the target and stops `BLOCKED` on any movement of base commit or branch, head, head repository or branch, state, or draft; each resolved role is reported with the provider, model, and thinking level the runner recorded. After validation, before the first gate, and again before every gate after the first and at final readiness, the driver re-reads the pull request, its body, the checkout (its HEAD must be the public head; a tracked or staged change anywhere, an untracked one outside the runtime roots, or a runtime root that is not a real directory stops `BLOCKED`, before and after validation too; the ignored paths outside the runtime roots and every descendant of an ignored directory, with their types judged without following a link and their content (a file's SHA-256, a link's target), are frozen after validation as the validation sandbox delta and any change to them stops `BLOCKED`), the issue specification, and every head fingerprint, and any change of the external snapshot since the evidence was collected (a record added, edited, or removed, a review dismissed, a check or status changing state), whether before a later gate or at final readiness, invalidates every gate verdict and reruns convergence within its cap, convergence at its cap handing the candidate to Sol. A convergence round at its cap that leaves findings open hands the candidate to Sol with those findings assigned through `build_gate_assignments` (CL-D62); an earlier round with findings open stops for the author. The driver's own Git reads run in the helpers' sanitized Git environment and safe Git configuration (no hook, fsmonitor, or external diff the checkout names) and its `gh` calls drop the Git redirection variables, so an inherited `GIT_DIR`, `GIT_WORK_TREE`, or `GIT_INDEX_FILE` never moves them off the checkout. The repository and the pull request, with every field the target binds, are read before the run directory is created, so a lookup that fails leaves no half-run. The driver reads the head and base from a local checkout; a foreign pull request, or one whose objects are not local, is refused before any run directory and stays with review-only.md's prose path until the prompt switch decides otherwise. A required check or status context that has not reported for the head is pending, branch protection's legacy `contexts` count beside its `checks`, and one pinned to an app (branch protection's `app_id`, where -1 or none accepts any source) is met only by that app's check run, never by another app's or a legacy status; and a reply or edit inside a review thread is new evidence. CL-D85's recorded Minors are the reword, follow-up, and out-of-scope ones; a criterion-anchored Minor stays open whatever it proposes, because whether its correction changes no file is not readable from the result; and a follow-up proposed `deferred` that is not a Blocker advances at any severity, as the validator already resolves it. Sol receives the trusted associations' comments and never a bot's. A head in another repository than the base is refused before any run directory, whatever objects are local. Final readiness then stops `WAITING_FOR_OWNER` on an unresolved review thread (an external finding the owner dispositions), `BLOCKED` on a failing check run or commit status or a reviewer's latest decisive review requesting changes (a bot's included), and `WAITING_EXTERNAL_REVIEW` on anything pending, including every requirement the snapshot cannot settle exactly, which waits for a human and never passes (owner decision https://github.com/tetsuh/pi-tidd-agents/issues/196#issuecomment-5892010180): the driver never decides whether a ruleset applies or whether approvals satisfy one, so every repository or organization ruleset not known `disabled` that carries a rule besides `deletion`, `non_fast_forward`, or `creation` is pending, whatever its targeting reads, and so is every enabled branch-protection setting the driver does not evaluate, its review requirements, strict required checks, and required linear history included (required checks and conversation resolution are evaluated, and `enforce_admins`, `allow_force_pushes`, `allow_deletions`, `block_creations`, and `allow_fork_syncing` never gate a merge); and so is any `mergeable_state` GitHub reports other than `clean`, `unstable`, or `has_hooks`, which covers protection or rulesets the token cannot read, a head behind its base, and a merge conflict; a skipped or neutral check passes, and a check conclusion or status state the driver does not know is unknown, which is not complete. An assigned finding the gate confirms is resolved on the unchanged head unless it still proposes `fixed` or `needs-owner-decision`. The bound repository is GitHub's canonical `base.repo.full_name`, whatever `--repo` spelled, and a diff that is not valid UTF-8 stops `BLOCKED` before any gate, because no gate could receive it exactly. Final readiness keeps review-only.md's two-minute quiet period after the latest external event and reports it with the fifteen-minute observation window measured from this run's first snapshot, for this run only; an event inside the quiet period is pending, and so is an external record without a valid event time, which cannot place it; a change the run observes without an event time of its own, such as a thread resolved, is timed when it was observed; and the window's end is reported beside anything still pending. The visible comment and the status block neutralise a command substitution and a carriage return in the untrusted text they quote, and each quoted value (a branch name, a command, a gate's or GitHub's text) is one line, folded as the publisher folds it (zero-width characters dropped, every space it folds, NEL included, made one space), that never carries the publisher's observation marker, which only the driver's own observation fields carry, so every draft stays publishable; `resolved:` names each role once, with its latest resolution; `next_action:` names only the stop's own permitted action; and `MERGE_READY` carries no invalidated evidence. The publication spells no local root (#221): in the free text it quotes (the reason, what the run observed of external review, validation, gate findings, pending decisions, operator actions, invalidated evidence, and next action), read as the publication folds it, the run directory, the package, the operator's home, and the temporary root are replaced by `{run-dir}`, `{package}`, `~`, and `{tmp}` where they are spelled as a whole path; a root is an absolute path without its trailing slashes, so the filesystem root itself is no root, and the home is both what `HOME` says and the account's own; a root is left where a letter, number, mark, `_` or `-` follows it, or a dot before a letter, number, mark or `_` (a longer name), and where a letter, number, mark, `/`, `.` or `~` stands directly before it (a longer path), except that leading slashes and an attached option, such as `-I` (its whole run of hyphens, an ASCII letter, then ASCII letters and hyphens, of any length), count as its start; a field that still spells a root after that pass, read as it is published with the full stop its template may add, is withheld whole behind a fixed phrase, never rewritten in part, so a generic root such as `/tmp` inside ordinary text withholds the field (owner decision REDACTION-FAIL-CLOSED on PR #223); exact fields are never rewritten; and the run's state and the operator's terminal report keep the full paths, the resume command included. A convergence role the parent's role preflight found disabled is passed as `--convergence disabled`: the run starts at Sol, and the status block reports `convergence: disabled` in `resolved:` and `rounds:` (CL-D62). One driver command at a time holds a run, through a `lock` directory taken before the state is read and released when the command exits, whose `pid` file is created exclusively and without following a link, and which a failed construction releases at once; another command on the same run, `status` included, is refused before it reads or writes anything. A gate still running is not a result, and a missing or unreadable result, a missing or malformed runner status record included, is relaunched once with the same request and no round spent, after the target is revalidated. CL-D107 later added a result whose correlation names no run (#254). CL-D110 later carried earlier rounds' findings into a fresh run and stopped one after five rounds without `MERGE_READY` (#259). A validation harness failure stops `BLOCKED`, never a verdict. `review.js resume` continues only a `WAITING_EXTERNAL_REVIEW` stop, recomputing every fingerprint, refusing a moved target, and reporting its own observation time; every other stop is completed by a fresh run. Once the run directory exists every failure ends with an outcome token, a status block, and publishable artifacts, and the report names both paths, the body digest, the one command, and the head binding, then carries the status block; `review-comment.md` and `publish-review.sh` are the only publication artifacts (CL-D33), and the block is kept in the run's state rather than as a file of its own. The status block is review-only.md's (`sol`, `terra`, the head OID, one finding per line). The review-only driver names no writing operation. `.tidd.json` sits at the repository root because `.pi` is a runtime root that `operator_capture` refuses to find tracked. The pull request that introduces this driver and this repository's `.tidd.json` cannot find the file at its own base; it is reviewed by the #191 spike driver, which validates with `node --test` without reading it, and every later pull request finds the file at its base.
*Rationale:* Every member of the class that began with CL-D56 ended with a composed document leaving the parent's hands; the driver removes the last of them at once, and the spike measured it on real runs rather than predicting it.
*Validity and invalidation conditions:* Applies to the driver directory and the review-only round it runs. The helpers, the gates, their authority, and the review-only outcome tokens are unchanged; the autofix driver and the prompt switch are later decisions of #196. CL-D104 later made the prompt switch: a pull request the driver sends back prints a last line beginning `PROSE_PATH:` and continues with Mode dispatch in the parsed mode. Giving the driver a writing operation, reading validation commands from the head, or computing `contractInput` from the target checkout requires a new owner decision. Readiness takes external findings only from unresolved review threads and review states: pull-request conversation comments and `COMMENTED` review bodies are not evaluated as findings, and the owner who merges reads them (https://github.com/tetsuh/pi-tidd-agents/issues/203#issuecomment-5900278433). CL-D97 resets it to 105,000 bytes. #241 later reset it to 110,000 bytes (https://github.com/tetsuh/pi-tidd-agents/issues/241#issuecomment-6003583084). CL-D100 later made external review best effort: the driver waits for no provider, quiet period, or observation window, and what only a human or GitHub settles is named in `operator_actions` instead of waiting for a human.
