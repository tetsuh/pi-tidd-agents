## CL-D39 — Exact autofix gains one bounded pre-writer recovery
**Clauses:** CL-D39-stop, CL-D39-recovery, CL-D39-baseline

*Decision ID:* CL-D39
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#34` at the current Issue #34 body, decided after review corrected the evidence
*Question:* May exact PR `autofix` recover in the same live run from a bounded, deterministic, pre-writer local tooling failure, and can that be added without splitting prose the modes share?
*Options and trade-offs:* Option A retains the universal stop and leaves the operational brittleness Issue #34 reported. Option B adds a bounded recovery. Option C waits for an executable durable controller. A is simplest but discards a full Sol and Terra round for an incidental local defect on an unchanged clean head. C changes nothing now and carries the largest scope.
*Recommendation:* Option B, scoped to exact PR `autofix` and expressed only in the mode reference that already owns retry behaviour.
*Owner choice:* Option B for exact PR `autofix`. One recovery is permitted per operation and phase for a deterministic local parsing, rendering, schema-access, or report-verification failure, and only when no mutation was attempted other than the already-authorized setup effects (`workspace_create`'s external run root, linked-worktree registration or clone, and receipt, and the packaged helpers' ephemeral process-isolation root `pi-tidd-pr-helper-*` with its `home`, `hooks`, `global.gitconfig`, `system.gitconfig`, and `git-stderr`), no correction, publication, provider, target, or operator mutation exists, no Luna task, commit, push, or reply exists, `OPERATOR_CHECKOUT_UNCHANGED@O` and `AUTOFIX_WORKSPACE@H` are freshly re-proved, and identity and every applicable fingerprint are unchanged. The failed operation is replaced by a prevalidated one rather than repeated. A second failure of the same operation and phase is terminal, and every post-writer phase stays terminal for every failure. Issue and PR review-only keep their existing single malformed-verdict retry unchanged.
*Rationale:* Issue #34 records these failures on a clean unchanged public head with no writer invoked, so the recoverable classes are real rather than hypothetical, and the alternative is discarding valid review evidence for an incidental defect. The validation-harness example is the exception: in the shipped phase model validation runs only inside Luna's focused batch or inside a gate child, both terminal, so that row is terminal here and its structural removal stays with #64. Narrowing since #34 was filed is real but partial and does not close the case: a closed envelope rejects unknown fields without preventing selection of the wrong known field, `fingerprint_pr_base`, `fingerprint_pr_tree`, and `fingerprint_pr_head` all accept an `oid`, so a same-typed cross-domain mix-up was reachable when this was decided; CL-D42 later labelled every fingerprint domain inside one versioned envelope, which closes the copy path and leaves only a value retyped by hand into a well-formed record, and the staged-manifest comparison is still orchestrator logic. The recovery is bounded to the pre-writer region precisely because exact autofix is the only mode carrying mutation authority: once Luna starts, the safety boundary and the recovery path would sit beside each other, so no post-writer phase is recoverable. No shared prose changes, and no shared sentence gains a mode exception: the shared gate contract already states that ordinary workflow-specific retry and fail-stop behaviour belongs to the selected owning workflow or mode reference, and that shared policy grants no retry, so the rule lives entirely in the mode reference that already owns it. Shared round accounting is unaffected because a recovery consumes no counter, exactly as a tool failure does not consume a round.
Each recoverable failure carries one canonical `operation@phase` key that its replacement retains, so a replacement failure is the second failure of that key and is terminal, and recovery preserves evidence already proved unchanged while invalidating only the failed operation's own output. Under `DEC-PR65-CLD39-WORKSPACE-MUTATION-001` the owner chose to exempt only those enumerated setup effects from the no-mutation guard, because `AUTOFIX_WORKSPACE@H` presupposes a created workspace and a literal guard would make the recovery unreachable; the exemption grants no setup authority that `workspace_create` did not already hold before any gate. Under `DEC-PR65-CLD39-PROCESS-ISOLATION-002` the owner added only the packaged helpers' process-isolation effects, which every helper Git invocation writes before recovery is reachable; the enumeration is pinned against the helper source so a new helper write fails the build until the exemption is revisited. The recovery binds to `OPERATOR_CHECKOUT_UNCHANGED@O` and `AUTOFIX_WORKSPACE@H`, the live invariant pair; `CLEAN@H` is not used because Issue #42 retired it. Holding the closed mapping raises the six-file authority baseline from 112,000 to 116,000 bytes: the mapping is required by Issue #34's own acceptance criteria and by review, Issue #58 already harvested cross-file duplication, and after the section's own restatements were removed the six files measured 112,720 bytes at `f7f3ff9`, when the raise was decided, and 112,798 bytes at `c5c7d43` after the concrete report replacement, so the shortfall is funded by the raise rather than by a trim.
*Validity and invalidation conditions:* Applies to exact PR `autofix` before any Luna task exists, and grants no resume, no second writer, no repeated provider mutation, and no relaxation of any guard, manifest, correlation, or public-head invariant. It changes no Issue or PR review-only behaviour and adds no shared-layer authority. Widening the recoverable set, raising the budget above one, extending recovery past the first Luna task, or applying it to another mode requires a new owner decision. Removing the mode-ownership statement from the shared gate contract invalidates the no-fork basis recorded here.
