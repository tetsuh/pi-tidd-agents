## CL-D111 — Every pull request runs through the driver; the prose path is refused
**Clauses:** CL-D111-record, CL-D111-skill, CL-D111-mode-dispatch, CL-D111-boundary, CL-D111-driver-refuse, CL-D111-driver-utf8, CL-D111-readme, CL-D111-forward, CL-D111-tests

*Decision ID:* CL-D111
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#249` at its body, the decision material (https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6105214013) and the owner decision on it (https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6105220135), with the order corrected in https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6105250786 and the stops confirmed in https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6105653537 (a refusal before any run, and `BLOCKED` for a non-UTF-8 diff)
*Question:* Since CL-D104 the driver sent three cases back to the prose path on a `PROSE_PATH:` line: a head in another repository, a base or head commit the checkout does not hold, and in review-only mode a diff that is not UTF-8. The parent then hand-composed the round from the four mode references, about 85 KB of authority that no process reads on the driver path. None of the three cases occurred on a consumer run (#244). Does the prose path stay?
*Options and trade-offs:* Option (a) refuses the prose path: the driver refuses or stops, the parent reports it, the mode references are deleted and the parent prose shrinks to the dispatch path. Option (b) keeps a single minimal reference for the three cases, a second specification for a path nothing exercises. Option (c) keeps #196 decision D2 as it is.
*Recommendation:* Option (a).
*Owner choice:* Option (a). A pull request of another repository than the current checkout's is refused by the parent before the driver, which reads a number only against the checkout's repository. A head in another repository, or a base or head commit the checkout does not hold, is refused before any run directory exists, on the driver's error output like any other target it cannot bind; the parent reports the refusal and stops. A review-only diff that is not UTF-8 stops `BLOCKED` with its artifacts drafted, as the autofix driver already did, and nothing follows the driver's own status line. The driver prints no `PROSE_PATH:` line, the dispatch section has no step for one, the Mode dispatch block is a non-operative note that names the driver and reads no reference, and the Skill's target-kind boundary states the refusal in place of the foreign review-only path; CL-D8's foreign rule is rescoped to the Issue workflow. The work is split so that each pull request is behaviour-neutral after this one: the mode references are deleted in later pull requests of #249, one per file for their clause pins and test reads, and a last one deletes the files, trims `SKILL.md` to the guard, mode parsing, the target boundary and the dispatch section, retires the guards that measured those files, and lowers the authority ceiling against a baseline measured on that change.
*Rationale:* One path with one specification, the driver code; a second specification for an unexercised path drifts from the driver without anyone noticing. Refusing before the run directory exists follows CL-D104's own rule that a refusal leaves no half-run behind. Reviewing a fork from the GitHub API, if it is ever wanted, is a driver capability to add, not a prose path to keep.
*Validity and invalidation conditions:* Applies to `/tidd-pr` and `/skill:closed-loop-pr` in both PR modes. The Issue workflow's foreign-target rule (CL-D8) is unchanged. Reinstating a hand-composed round, or reviewing a pull request from the GitHub API alone, requires a new owner decision.
