## CL-D25 — Validated `pi-subagents` minimum, and what a normal commit is
**Clauses:** CL-D25, CL-D25-minimum, CL-D25-commit, CL-D25-commit-publish, CL-D25-commit-record, CL-D25-commit-shape, CL-D25-commit-check

The validated minimum is `0.70.0`, verified as the version installed in the validating environment. It was `0.36.0` until 2026-09-20, when Sol raised ADV-158-RECEIVER-MINIMUM-DRIFT on PR #158 and the owner raised the minimum (https://github.com/tetsuh/pi-tidd-agents/pull/158#issuecomment-5748636592). The old minimum had already stopped being true: `checkpointBeforeDeadlineMs` arrived in `0.68.0`, and CL-D80 fixed it in the writer launch, so this package required more than `0.36.0` from that record onward. It rose again the same day, from `0.69.0` to `0.70.0` (#160): `0.70.0` ships compiled JavaScript where `0.69.0` shipped TypeScript, so the receiver regression drives the modules pi itself loads and an install below it carries none of them. The rule is unchanged — the minimum is the version this package is validated against, raised when a record requires a newer receiver — and a run on an installed receiver below it fails naming this minimum rather than skipping its receiver checks. From `0.72.0` pi-subagents takes `typebox` from pi rather than bundling it, so the receiver regression resolves it for the receiver's ES module imports from the installed pi package when the receiver's own manifest cannot, records which source it used, and still fails naming this minimum when neither resolves (#197). pi-subagents 0.78.0 is validated (#287). From 0.77.0 the `subagent` tool schema types a dozen top-level fields, among them `agent`, `task`, `async` and `cwd`, and the rest only inside `options`, keeping a field given at the top level as it is, so its schema no longer types the `context`, `outputMode`, `acceptance`, `timeoutMs` and `checkpointBeforeDeadlineMs` the builders emit at the top level; the receiver's flat schema still types each of them, the builders' own tests hold their values, and they stay at the top level, where every receiver from the minimum accepts them. A normal commit follows Conventional Commits, carries the issue number, and states test provenance in its body when covered behaviour changes. Its body is a bullet list (#166): line 1 is the subject, line 2 is blank, and every line from line 3 on is a bullet, one claim per bullet, with the RED and GREEN measurements as their own bullets, each naming its exact command; trailers stay as trailers after a blank line. The driver's correction commits take that shape, and this repository's own non-merge commits are checked for it from 2026-09-27, the day after the last non-conforming body. The commit convention is not machine-checked on a consumer repository, except the exact-autofix correction subject, which CL-D116 checks.
