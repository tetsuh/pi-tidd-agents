## CL-D84 — The terminal cleanup is one packaged operation
**Clauses:** CL-D84-map, CL-D84-record, CL-D84-tests

*Decision ID:* CL-D84
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#161` at its body and the owner choice https://github.com/tetsuh/pi-tidd-agents/issues/161#issuecomment-5750547876 (working session of 2026-09-20)
*Question:* The exact-autofix run on PR #149 assembled the terminal cleanup request itself and wrote a `cwd` into it; CL-D76 refuses that field, so the run kept a workspace root and drafted no publication artifacts. Every other request the parent used to assemble has a builder, and the map already says this one takes no `cwd`. Does the prose stay the guard, or does the composition leave the parent?
*Options and trade-offs:* Option A leaves the refusal as the only guard: no new operation, and the same accident recurs, as it has four times under CL-D56, CL-D68, CL-D73, and CL-D81. Option B packages the terminal cleanup as one operation that takes the run's own `workspace_create` result and composes and runs the request inside the package, so there is no document for the parent to widen; it costs one operation and one declared field. Option C loosens `build_workspace_cleanup` to tolerate a `cwd` that matches the receipt, which is the relaxation CL-D76 was taken to prevent.
*Recommendation:* Option B.
*Owner choice:* Option B. `workspace_cleanup_created` takes `created`, the data of `workspace_create`, and nothing else; it composes the CL-D76 request inside the package, runs it, and returns what `workspace_cleanup` returns, so a run reports what it always reported. A `cwd` beside it, any other field, or a missing workspace is refused by the CLI's own input table; a clone fallback and a receipt that is not `workspace_create`'s are refused at phase `build`, and a refused cleanup removes nothing. `build_workspace_cleanup` and `workspace_cleanup` remain for a caller that already holds the request, unchanged.
*Rationale:* The refusal was correct and the run still ended badly, because the only thing standing between a correct rule and a lost run was the parent typing the right document. Four earlier members of this class ended the same way, and each time the answer was to remove the document rather than restate the rule.
*Validity and invalidation conditions:* Applies to the terminal cleanup in exact autofix. It grants nothing new: the cleanup authority, its identity reverification, and CL-D76's refusal of a caller `cwd` are unchanged, and no other operation changes. Accepting another input, performing the cleanup anywhere but the repository the receipt states, or continuing a run past a refused cleanup requires a new owner decision.
