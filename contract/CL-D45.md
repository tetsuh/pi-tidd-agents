## CL-D45 — Source replies carry deterministic markers and reconcile read-only
**Clauses:** CL-D45-autofix, CL-D45-map, CL-D45-readme, CL-D45-tests

*Decision ID:* CL-D45
*Kind:* fail-closed reply idempotency and reconciliation boundary
*Target and revision:* `tetsuh/pi-tidd-agents#40` at its initial body and the owner's live instruction `#40 を進めて`; the Option A choice follows the issue's own recommended initial policy and is approved by the owner in the authoritative pull-request comment <https://github.com/tetsuh/pi-tidd-agents/pull/77#issuecomment-5451155083>
*Question:* After a reply attempt whose outcome is unknown, how may the workflow learn what actually happened without gaining any right to act on the answer?
*Options and trade-offs:* Doing nothing leaves `reply_outcome_unknown` permanently undiagnosable, so every ambiguous transport outcome costs a full owner investigation. Option A adds a deterministic marker and a read-only reconciliation that classifies refetched evidence, with every outcome terminal. Option B additionally permits exactly one new POST after a conclusive `reply_confirmed_absent`, which requires trusting the absence classification with mutation authority. A adds observability and no authority; B turns a read-back into a retry authorization and stands or falls with the completeness of one listing.
*Recommendation:* Option A, as the issue itself recommends for the initial policy.
*Owner choice:* Option A. Every reply body ends with one deterministic `pi-tidd-agents:source-reply:v1` marker binding the schema version, repository and pull request, source identity and body digest with both timestamps, exact public head, finding IDs with confirmed dispositions, confirming gates, corrective commit or `none`, and the visible-body digest. `visibleSha256` covers the canonical visible bytes alone and the marker line sits outside them, so the definition is non-circular, and a visible body containing a marker line is rejected. `marker_reconcile` classifies supplied refetched evidence as exactly one of `reply_confirmed_published`, `reply_confirmed_absent`, `reply_ambiguous`, or `reply_conflict`: only an exact one-marker, one-body match on complete evidence is published, insufficient evidence is ambiguous, contradictory evidence is a conflict, and absent requires complete evidence. Every outcome is terminal for the run; no second POST exists under this decision, and a fresh owner-authorized run remains the only continuation.
*Rationale:* `REPLY_EXCEPTION` is deliberately one-shot, so an ambiguous transport outcome could previously be resolved only by a person reading the PR. The marker makes the one allowed reply self-identifying — the same discipline CL-D42 applies to evidence values and the review-publication marker applies to aggregate summaries — and reconciliation is deliberately split from mutation: it is a pure function over evidence the caller refetched through the packaged snapshot, reaches no filesystem, process, or network primitive, and therefore cannot retry, resolve, or post regardless of its result. Classification is asymmetric on purpose: published demands an exact one-marker, one-body match because it is the claim a later run will rely on to exclude the reply from intake; absent demands complete pagination because an incomplete listing can hide the reply itself; everything contradictory is a conflict for the owner rather than a guess. Option B was declined because a second POST authorized by an absence classification concentrates exactly the trust the one-shot rule exists to avoid; nothing in the marker design precludes a later owner decision adopting B without changing the grammar. This decision declares no CL-D44 field: the two operations take plain request data, no cross-operation envelope, data, or receipt composition is introduced, and adding one would require a new owner decision under the CL-D44 freeze. It also changes no reply-attempt semantics: `reply_outcome_unknown`, the no-retry rule, batch ordering, and the post-reply readiness guards are untouched, and the existing marker-verified intake exclusion now has the exact grammar it presupposed. Sol round 1 hardened four edges and each correction is recorded: the digested visible form is LF-terminated so a body authored without a final newline still round-trips to published; source kinds and dispositions bind to their recorded vocabularies while finding IDs stay as open as the gate contract allows, rejecting only serialization-breaking characters; the source URL must address the bound repository and pull request, so contradictory identities cannot ride in one binding; and reconciliation requires the expected workflow author, so a byte-exact copied marker from any other author is a conflict rather than the workflow's published reply, and a comment carrying no authorship is insufficient evidence. Round 2 hardened two more: the serialized marker line must contain exactly its own final HTML-comment terminator, so a gate-valid value containing `-->` is rejected instead of ending the hidden comment early and leaking the remainder as visible text; and source timestamps must be real canonical UTC instants, round-tripped through the calendar, so a shape-valid impossible date can no longer serialize or reconcile. Terra round 1 closed the terminal-position escape: the marker ends the reply body, so the LF-terminated comment must end with the marker line and the digest covers only the preceding prefix — a marker moved to the front or middle reconstructed the same visible bytes under the old any-position removal and passed as published. Round 3 closed the altered-marker escape: a current-v1 marker prefix outside a canonical marker line, naming the bound source or too mangled to rule it out, is a conflict rather than absence, while a candidate naming another source and any unknown marker version leave absence undisturbed. Round 4 reopened that finding with noncanonical internal whitespace — a TAB or vertical TAB for the single-space separator hid the source binding inside a canonical-looking line — and closed it structurally: canonical recognition is re-serialization equality rather than prefix and suffix, and candidate tokens split on any whitespace, so an altered interior can neither pass as canonical nor conceal which source it names. Round 5 closed the last seam of the same class: detection matches the version-token stem separately from its canonical single-space delimiter, so replacing the space after `v1` itself is altered evidence too, while a longer version token remains outside this vocabulary. Round 6 closed two evidence-integrity gaps: candidate diagnosis retains every source-binding occurrence, so duplicated or contradictory bindings are a conflict and absence requires exactly one binding unambiguously naming another source; and a destination comment without a stable provider ID is insufficient evidence, so an exact match can never publish under a fabricated identifier. Round 7 made the precedence order-independent: every destination comment is prevalidated in full before any contradiction is examined, so the same evidence classifies identically in every arrival order and insufficient evidence is genuinely judged first.
*Validity and invalidation conditions:* Applies to exact PR `autofix` source replies. Reconciliation grants no mutation, retry, resume, thread-resolution, approval, or summary authority, and consumes no counter. The marker grammar is versioned: an unknown version never matches, and changing the field set, the digest domain, or the classification vocabulary requires a new owner decision. Adopting Option B, or acting on any classification with a provider mutation, requires a new owner decision recording its separate grant. If the packaged snapshot ever stops being the sole refetch path for reply evidence, the read-only basis recorded here is invalidated.
