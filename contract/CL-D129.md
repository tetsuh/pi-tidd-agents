## CL-D129 — The ignored-path inventory records presence and type only, as CL-D38 defines
**Clauses:** CL-D129-record, CL-D129-driver, CL-D129-forward, CL-D129-tests

*Decision ID:* CL-D129
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#332` at its body, the owner's choice of the recommended option
*Question:* Both drivers freeze the ignored-path inventory once validation ran and compare it at every later boundary. The inventory hashed each ignored file's content and recorded each link's target, where CL-D38 defined the validation sandbox delta as a presence delta; CL-D119 recorded that divergence and did not close it. Gates may run the tests, and a test run rewrites ignored files such as a test log, so a review stopped `BLOCKED` because its own gate ran the tests (#332). What does the inventory record?
*Options and trade-offs:* Option A records presence and type only, as CL-D38 defines: a rewritten ignored file no longer stops a run, while a new, removed or retyped ignored path still does. Option B keeps the content and adopts the ignored changes a gate makes during its run: the run keeps going after a gate's test run, but it adds a second freeze point per gate and still lets the content enter the comparison. Option C keeps the inventory and asks operators to configure validation commands so the tests run before the freeze: it fixes nothing when a gate runs them anyway.
*Recommendation:* Option A.
*Owner choice:* Option A. `ignoredInventory` in `skills/closed-loop-pr/driver/run.js` lists each ignored path outside the runtime roots and every descendant of an ignored directory, and each entry records its path and its type (`dir`, `file`, `symlink`, `other` or `absent`), never a file's hash or a link's target. Both drivers compare it as before: at every boundary of the review-only driver, before every gate of the autofix driver, and in the writer batch. This closes the divergence CL-D119 recorded.
*Rationale:* CL-D38 already chose presence: the delta is observed only, never read, and no cache content enters evidence. A rewritten ignored file reaches no gate and no published artifact, so stopping on it protects nothing and stops reviews whose gates ran the tests. A new, removed or retyped ignored path still stops the run.
*Validity and invalidation conditions:* Applies to the ignored-path inventory of both packaged drivers. Tracked, index, ref and untracked-path checks are unchanged. Reading an ignored file's content, adopting a gate's ignored changes, or excluding paths from the inventory requires a new owner decision.
