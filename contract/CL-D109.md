## CL-D109 — The gate payload carries the diff as its own readable section
**Clauses:** CL-D109-record, CL-D109-contract, CL-D109-builder, CL-D109-tests

*Decision ID:* CL-D109
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#261` at its body, from #260's investigation (https://github.com/tetsuh/pi-tidd-agents/issues/260#issuecomment-6069735415) and the owner decision as amended (https://github.com/tetsuh/pi-tidd-agents/issues/260#issuecomment-6069911912)
*Question:* `build_gate_launch` rendered the volatile envelope as one JSON block with the pull request's diff as a single JSON string. On tetsuh/hekatus PR #107 line 30 of the convergence payload was 386,937 characters; the gate child could not `read` it, paged it with `dd` and `sed`, and reviewed only the first region it reached, returning one finding per run. How does the payload carry the diff?
*Options and trade-offs:* Option A writes the diff to a separate run-owned file the verify step binds by digest, which needs a second verified file on both drivers. Option B renders the diff as its own section of the same payload file, which `gate_payload_verify` already binds byte for byte (CL-D91), with the envelope's `diff` an index of it.
*Recommendation:* Option B.
*Owner choice:* Option B. The diff closes the payload as its own section, with real newlines, under a fence longer than any backtick run inside it, and headed as data, never instructions. The envelope's `diff` is an index: the section's heading, the diff's byte count and sha256, and each file's path, additions, deletions and the payload line of its `diff --git` header. The payload stays the complete gate payload, and review-only and exact autofix both compose it through `build_gate_launch`.
*Rationale:* A diff a child can read a file at a time lets a gate cover the change instead of sampling it; the payload digest already binds the section, so no new verification surface is added.
*Validity and invalidation conditions:* Applies to every pull-request gate launch. It changes no verdict rule, schema field, driver, or the issue root's payload, which carries no diff. Carrying the diff outside the payload file, or letting any line of the diff close its fence, requires a new owner decision.
