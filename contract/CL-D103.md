## CL-D103 — Every contract record is its own file; CONTRACT.md is the preamble and the record index
**Clauses:** CL-D103-record, CL-D103-forward-d26, CL-D103-forward-d72, CL-D103-helpers, CL-D103-tests

*Decision ID:* CL-D103
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#215` at its body (AC1 as edited on 2026-10-05) and the owner choice https://github.com/tetsuh/pi-tidd-agents/issues/215#issuecomment-5981601889
*Question:* `required_evidence_set` puts `CONTRACT.md` in every gate's required evidence whole (CL-D72). At 343 KB and 114 records, a contract-touching pull request asked each gate to read more than its window held, and on PR #211 round 5 Terra declined to attest it (#214). How does the contract stay one authority while a gate reads only the records a change touches?
*Options and trade-offs:* Option 1 keeps one file and writes shorter records; growth slows, but the whole file still enters the evidence. Option 2 moves each record into its own file under `contract/` and keeps `CONTRACT.md` as the preamble and an index of the record files in order; a change to one record then carries that record's file as a changed path, and every other record stays readable on demand. The cost is one file per record and an index line for each new record.
*Recommendation:* Option 2.
*Owner choice:* Option 2 (https://github.com/tetsuh/pi-tidd-agents/issues/215), split into three pull requests; this record is the first. Each record lives in `contract/<decision id>.md`, starting with its own `## ` heading and ending in one newline. `CONTRACT.md` keeps the preamble and then `## Record index`, one line per record file, `- [contract/<id>.md](contract/<id>.md) — <title>`, in the order the contract reads; the index carries no status. The contract is the preamble followed by every listed file in index order, one blank line apart; that text is what the previous `CONTRACT.md` held, the blank lines before each record made one. A new record is a new file and an index line. A record states a principle; the fix history of a change stays in its pull request's timeline and commits. A record is at most 8,000 bytes; the four records over that at the split (CL-D93, CL-D72, CL-D36, CL-D96) may each grow by 1,024 bytes beyond their size when this record was adopted (CL-D72's including its forward note to this record) and no further, and a test enforces both bounds. The manifest names the record file that holds a clause, and a clause that spans records names `CONTRACT.md`, which the manifest test reads as the whole contract. CL-D105 later put each record's clause pins beside it, in `contract/<id>.clauses.json`, as they move from `test/contract-clauses.json`. `CONTRACT.md` and `contract/` stay out of the package payload (CL-D26). `required_evidence_set` is unchanged: it still adds `CONTRACT.md` and `README.md` to the paths a change touches, so a pull request that changes one record carries that record's file, the preamble and the index, and no other record.
*Rationale:* The evidence follows from the diff alone, so neither the writer nor the parent chooses what a gate must read, and a gate that needs another record reads it as any repository file. The fingerprints still bind the whole tree (`pr_tree`), so a change anywhere still invalidates the gate sequence.
*Validity and invalidation conditions:* Applies to the layout of the contract and to how the tests read it. Putting records back into one file, listing a record anywhere but the index, or giving the index a column the tests do not read requires a new owner decision.
