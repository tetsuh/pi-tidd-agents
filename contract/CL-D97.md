## CL-D97 — Validation commands without a committed .tidd.json
**Clauses:** CL-D97-record, CL-D97-forward, CL-D97-tests

*Decision ID:* CL-D97
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#209` at its body, whose "Owner decision (2026-09-30)" section records the choice, and the ordering https://github.com/tetsuh/pi-tidd-agents/issues/209#issuecomment-5913850450
*Question:* CL-D93 reads the validation commands only from `.tidd.json` at the base commit, so a repository without the file cannot run a driver at all; `tetsuh/sitometron` stopped there. The requirement's purpose is that the pull request under review cannot choose the commands the driver runs, and any source outside the pull request meets it. Where else may the commands come from, and what happens with none?
*Options and trade-offs:* Option A runs without validation commands, only `git diff --check`, and says so; nothing to configure, and the driver runs no tests. Option B guesses the commands from the repository's build files, which is unreliable on mixed toolchains. Option C reads an operator-side configuration outside the repository, or an explicit launch argument, which neither the pull request nor the target repository writes.
*Recommendation:* C, then A.
*Owner choice:* C and A combined. The commands resolve in this order: `.tidd.json` at the base commit; otherwise `--validate` when given, a JSON list of argv lists, else the operator's configuration at `$XDG_CONFIG_HOME/tidd/<owner>/<repo>.json` (`~/.config` when unset or relative) in the base file's format; otherwise none. The head is never a source, and the run records the source it used and names it first in the validation line. Review-only with none runs `git diff --check` only, proceeds to the gates, and says "no validation commands configured" in the validation line and in the status block's `operator_actions`, which names where to add them as `~/.config/tidd/<owner>/<repo>.json` rather than the operator's own path. Exact autofix with none stops `BLOCKED` before the operator capture, naming both places, because its writer commits and pushes. Guessing from build files is declined. This record lands before #196's prompt switch, so the switch needs no file in any target repository. The operator configuration path is resolved as the kernel resolves it, its `.` and `..` included, and the aggregate driver alarm resets from 100,000 to 105,000 bytes for that walk (https://github.com/tetsuh/pi-tidd-agents/pull/211#issuecomment-5964873013). #241 later reset it to 110,000 bytes for the relaunch of a failed step that wrote no output (owner decision https://github.com/tetsuh/pi-tidd-agents/issues/241#issuecomment-6003583084): the driver files measured 105,250 bytes on that change, leaving 4,750.
*Rationale:* The base file's guarantee was that the reviewed change cannot pick what runs; an operator's own file and an operator's own argument give the same guarantee without touching every target. Review-only judges a pull request with or without a suite, and the gates can still run one themselves; a correction batch needs one before it commits.
*Validity and invalidation conditions:* Applies to both drivers' validation source. A malformed base file, a malformed `--validate`, or a malformed or unreadable operator file (anything but a missing entry: a dangling link, at the file or above it, or a non-file included), or one inside the target checkout, judged by resolving the path link by link as the kernel does and checking every folder passed against the repository root's device and inode, so a link at any depth, including a tracked link leading out again, a subdirectory checkout, or a case-insensitive spelling cannot hide it, stops `BLOCKED` before any gate, as does a base commit the checkout does not hold, and every file source is read as bytes that must be at most 64 KiB of BOM-free, well-formed UTF-8 before it is parsed, so an executed argv is exactly the file's text (`--validate`, spelled `--validate <json>` or `--validate=<json>`, arrives as an already-decoded argument and stops if the decoding replaced any byte), and the base file still wins when present. Reading commands from the head, guessing them, or letting exact autofix run without them requires a new owner decision.
