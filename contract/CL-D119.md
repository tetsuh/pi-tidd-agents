## CL-D119 — The PR Skill is trimmed to its dispatch and the four mode references are deleted
**Clauses:** CL-D119-record, CL-D119-notes, CL-D119-tests

*Decision ID:* CL-D119
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#295`, pull request C2 of #249, under the owner's PR C decisions (https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6179573061) and their C2 refinements (https://github.com/tetsuh/pi-tidd-agents/issues/249#issuecomment-6208636108), after C1 (CL-D118)
*Question:* Since CL-D111 no run takes the prose path, and B1 to C1 moved every pin and every rule off `references/review-only.md`, `autofix.md`, `autofix-addendum.md` and `helper-map.md`. How are they deleted, and how far does the PR Skill shrink, without losing what the driver and the gates still read?
*Options and trade-offs:* As the PR C decisions state.
*Recommendation:* As the owner chose.
*Owner choice:* The PR Skill keeps its frontmatter and title, the shared references, the precondition guard, mode parsing, preflight, the target-kind boundary, driver dispatch and `### PR gate role-authority blocks (CL-D2)` under its parent heading; three kept sentences that pointed at removed text are reworded. The role block's heading and its two role lines are byte-identical, because `helpers/launch.js` reads them on every gate launch, and its last sentence, which pointed at the mode references, goes. The four files are deleted. Both drivers' `CONTRACT_INPUT_FILES` name the PR Skill and the two shared references alone, so both hash the same three files; a run started before the change keeps the `contractInput` it stored at `start`. Five shared-reference sentences change (`records.md` three times, one of them removed; `gate-contract.md` twice), which the Issue root reads too; no gate payload block changes. `AUTHORITY_FILES` measures four files. The 57,160-byte disclosure guard and the 32,000-byte addendum guard retire with the files they measured. The four authority files measured 74,363 bytes on this change, so the ceiling falls to 81,000 bytes on the CL-D43 terms, leaving 6,637 bytes. The Skill's removed pins move: CL-D9-pr to `driver/run.js`, with CL-D9-serialization (`helpers/fingerprints.js`) and CL-D9-brackets (`helpers/evidence.js`) new, CL-D9-roots keeping the Issue Skill; AC-DISPOSITION-pr to `helpers/gate-result.js`; CL-D38-definition to `driver/phases.js`; CL-D67-template and CL-D95-template to their records, which alone state the body template now; CL-D8-foreign takes the kept local-objects sentence. CL-D30-source-schema retires as a duplicate of AC-DISPOSITION-pr, and AC-DECISION-pr-scope and CL-D111-mode-dispatch with the prose path. The PR Skill's own pauses before dangerous operations and ship decisions, and its owner approval for merging without required deterministic coverage, lapse with it (AC-DECISION, AC-DISPOSITION). The tests' `readAutofixProcedure` and `test/issue-55-helper-invocation-map.test.js` retire; the B1 to C1 inventories assert the files are gone; the CLI operation table is pinned exactly, required fields included, in `test/issue-59-helper-surface.test.js` in place of the map-to-CLI check; and `test/issue-295-mode-references-deleted.test.js` names every test that still names a deleted file. Each record that stated a deleted file as live, a removed rule, or a retired guard carries a forward note naming this record; CL-D96 drops its pointer to `autofix.md` instead. Index lines stay equal to their headings (CL-D103).
*Rationale:* Nothing reads the deleted text, and every rule it carried has a home in code or a record; what remains in the Skill is what the parent and the gate launch read.
*Validity and invalidation conditions:* Applies to the PR Skill, the four deleted files and the guards that measured them. The ignored-path inventory the drivers compare hashes each ignored file's content and a stop names the changed entries, where CL-D38's definition observed presence only, recorded and not closed (#249, CL-D119). The Issue #10 reference model in `test/closed-loop-regressions.test.js` and the generic "mode reference" wording left in the shared gate contract stay as they are. Restoring a mode reference, or raising the ceiling, requires a new owner decision.
