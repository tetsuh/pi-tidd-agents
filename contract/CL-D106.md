## CL-D106 — A record is written only for a decision that changes an obligation
**Clauses:** CL-D106-record, CL-D106-preamble

*Decision ID:* CL-D106
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#250` at its body, and item 3 of the owner decision on #235 (https://github.com/tetsuh/pi-tidd-agents/issues/235#issuecomment-6018998245)
*Question:* The contract grew by six records in one week (CL-D100 to CL-D105), and several earlier records exist only to set an alarm value, a ceiling, a path or a wording. Records are rarely retired: the #235 L2 classification found 2 of 117 superseded. Which choices get a record of their own?
*Options and trade-offs:* Option 1 keeps writing a record for every owner choice, which keeps each choice findable by id but grows the contract without bound. Option 2 writes a record only for a decision that changes an obligation and records the rest where the value already lives.
*Recommendation:* Option 2.
*Owner choice:* Option 2. A contract record is written for a decision that changes what a gate, the writer, or the driver must or must not do. A choice that only sets a figure, a path or a wording, such as an alarm or ceiling value, a file location, or a sentence's phrasing, gets no record of its own: it is recorded in its issue thread and, where an existing record states the value, as a forward note in that record ("CL-Dnn later …") that cites the owner decision permitting it. Records written before this one stay as they are.
*Rationale:* A gate reads the records a change touches; a forward note in the record that already holds the value keeps that value beside its rule, while a separate record for each value scatters one rule across several files.
*Validity and invalidation conditions:* Applies to every record written after this one. Writing a record for a figure, path or wording choice alone, or recording an obligation change only in an issue thread, requires a new owner decision.
