## CL-D46 — Embedded repositories in the inventory are entries, not crashes
**Clauses:** CL-D46-tests

*Decision ID:* CL-D46
*Kind:* fail-closed enumeration boundary correction
*Target and revision:* `tetsuh/pi-tidd-agents#78` at its initial body and the owner's live instruction to proceed in parallel; the mechanism was narrowed during implementation from the issue's trailing-slash-directory hypothesis to the verified embedded-repository emission
*Question:* May the operator inventory accept the one entry shape Git itself emits for an embedded repository — a path with a single trailing separator — without weakening the path guard for any other caller?
*Options and trade-offs:* Rejecting (the prior state) fails `operator_capture` on every checkout carrying an embedded repository, which a vcpkg cache always does, with a message blaming dots; accepting everywhere would loosen a shared guard that other surfaces rely on; accepting exactly one trailing separator at the enumeration call site keeps the shared normalizer strict and matches precisely what Git emits.
*Recommendation:* Strip exactly one trailing separator at the enumeration boundary only, and split the rejection message so it names the failing component class and the offending entry.
*Owner choice:* As recommended. `git ls-files --others` emits an embedded repository as one entry with a trailing slash, in both the ignored and the untracked listings — verified by fixture, with the raw emission pinned so a change in Git's behavior surfaces. The inventory strips exactly that one separator before normalization; the shared `normalizeCheckoutPath` rejects trailing separators for every other caller exactly as before, and its messages now read `empty path component rejected: <entry>` and `dot path component rejected: <entry>` instead of the combined pathless wording. A doubled separator, which Git never emits, still fails closed; the one-strip property has no black-box witness and is pinned structurally.
*Rationale:* Observed on `tetsuh/sitometron` autofix runs: 247 logged occurrences of `capture_failed: empty or dot path rejected` on a checkout whose vcpkg cache contained registry clones, with gates 0/15 and pushes 0/5 on every attempt and a clean operator checkout — the repository could never pass preflight, and the pathless message misdirected diagnosis toward dot-prefixed paths for several rounds. The stripped entry is still a normalized checkout-relative lexical path with a no-follow kind, so the inventory contract's wording is unchanged and no authority prose moves. An ignored embedded repository is inventory like any other ignored directory; an untracked one still blocks as an unexpected untracked path — by policy, no longer by crash.
*Validity and invalidation conditions:* Applies to the operator inventory enumeration only. No traversal, absolute-path, NUL, `..`, or dot-component rejection is weakened anywhere, and no other caller of the normalizer gains the allowance. Accepting more than one trailing separator, moving the allowance into the shared normalizer, or restoring a rejection message that omits the offending entry requires a new owner decision.
