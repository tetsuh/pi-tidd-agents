## CL-D66 — Same-class rigor gaps are named once and written exactly the first time
**Clauses:** CL-D66-payload, CL-D66-writer, CL-D66-record, CL-D66-tests, CL-D66-sweep, CL-D66-sweep-tests

*Decision ID:* CL-D66
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#119` at its body and the design comment recording the owner choice https://github.com/tetsuh/pi-tidd-agents/issues/119#issuecomment-5600016151 (working session of 2026-09-08)
*Question:* Six of PR #113's eight post-acceptance adversarial rounds were one class of finding, delivered one per round and fixed one check at a time: a presence, substring, or subsequence test where the criterion called for an exact comparison. Under exact autofix that history exceeds the five-push cap and trips the no-progress breaker. Where should the exactness judgment be placed so a fix is made once?
*Options and trade-offs:* Option A adds one sentence on each side: the adversarial gate names every check of the same class in the result that rejects one, and the writer writes such checks as a complete parse plus an exact ordered comparison the first time. Option B changes the gate side only, so the writer's first attempt stays presence-shaped and the class recurs on the next surface. Option C is a deterministic lint over test files, which classifies open-world test code and is declined as the proxy-guard shape CL-D43, CL-D44, and CL-D48 recorded. Option D raises the CL-D30 caps, which buys rounds instead of removing their cause. Issue #126 extends this record from one check to one component, with its own three options: Option A adds one sentence beside the same-class rule; Option B has the parent re-invoke the gate against the named component after each finding, which costs a counted gate and a full review and is declined; Option C changes nothing and leaves the writer and the pre-push sweep carrying the whole burden.
*Recommendation:* Option A.
*Owner choice:* Option A. The Sol-only payload block states that when a finding rejects the rigor of a check, the gate names every check of the same class across the target in that one result, so the correction is made once. The writer section states that a check the writer adds or corrects against a declared list or block is written as a complete parse of the surface and an exact ordered comparison with the derived expectation, never as a presence, substring, or subsequence test. Two sentences in prose the gate and the writer already copy verbatim (CL-D2); no code, no new guard, no cap change. Issue #126, owner choice A (https://github.com/tetsuh/pi-tidd-agents/issues/126#issuecomment-5671862619), extends the same economy from one check to one component: the Sol-only payload block also states that when a finding exhibits a counterexample against a component, the gate attempts every other counterexample class against that same component — its other inputs, encodings, syntax forms, and boundaries — and reports all that succeed in that one result, so the component is corrected once. On PR #124 that class cost five rounds on the static spawn guard, three on `required_evidence_set`, and two on `validation_run`.
*Rationale:* CL-D63 placed surface-agreement gaps in the deterministic layer and told the gate to enumerate the rest in one result; this decision applies the same rule to test-rigor gaps, which no deterministic check can decide without classifying test code. The gate raises the class only when a criterion, clause, or invariant calls for exactness, so the sentence widens what one result carries, not what counts as a finding. The writer sentence removes the cause on the other side: a check written exactly the first time has no class to recur.
*Validity and invalidation conditions:* Applies to the Sol-only payload block and the exact-autofix writer section; verdict vocabulary, gate authority, the CL-D30 caps, and the CL-D63 fence-grammar bound are unchanged, and a presence check where presence is the criterion is not a finding. Adding a lint over test code, raising a cap, or letting the writer's own judgment replace a criterion's stated comparison requires a new owner decision. The Issue #126 component sweep changes no verdict rule, no severity, no anchoring class, and no round budget, leaves the convergence and Terra payloads untouched, and ends where the gate's evidence ends: a counterexample is still required, an absent record is still not itself a finding, and a claim whose evidence is unavailable is still reported as unverifiable.
