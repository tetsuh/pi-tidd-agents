## CL-D105 — Each record's clause pins live beside it
**Clauses:** CL-D105-record, CL-D105-preamble, CL-D105-forward-d103, CL-D105-tests

*Decision ID:* CL-D105
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#240` at its body, part (b1) of `tetsuh/pi-tidd-agents#234`, which carries part (b) of the owner choice on #215 (https://github.com/tetsuh/pi-tidd-agents/issues/215#issuecomment-5981601889)
*Question:* Since CL-D103 every record is its own file, but its clause pins still lived in the one shared `test/contract-clauses.json` (384 clauses, about 230 KB), so a pull request that added or changed a record's pins changed that file and carried it whole into each gate's required evidence. Where do a record's pins live?
*Options and trade-offs:* Option 1 keeps the shared file. Option 2 puts each record's pins in a file beside it, `contract/<id>.clauses.json`; a change to one record and its pins then carries those two files, and the tests read every pin through one assembly. Option 3 puts the pins inside the record as a fenced block; about twenty records would pass the 8,000-byte limit of CL-D103 with their pins, and a pin naming its own record would find its required text in its own fence.
*Recommendation:* Option 2.
*Owner choice:* Option 2, as #234 sets out for #215 part (b). A record's pins live in `contract/<id>.clauses.json`, which holds exactly `{"clauses": [...]}` with at least one clause: the same clause objects as before, with the keys each had, in the relative order they had in the manifest. A structural record has none. The ids in a clause file equal its record's **Clauses:** line as a set; the line's order is free. The tests read the pins through one assembly in `test/helpers.js`, `readManifest`: the residual `test/contract-clauses.json` while it exists, then each indexed record's clause file in index order, each checked for duplicate keys and each clause file for its shape, concatenated, so a clause left in two places fails as a duplicate. `contract/` holds only indexed records and their clause files, each a regular file. A clause that pins a forward note in another record's file (`CL-D104-forward-ceiling` pins `contract/CL-D43.md` and `contract/CL-D85.md`) stays in the clause file of the record that wrote the note, so editing that sentence touches the writer's clause file. This record moves only its own clauses; moving the rest and removing the residual closes #234 in a later pull request.
*Rationale:* The evidence follows from the diff alone (CL-D103), so a change to one record and its pins carries `CONTRACT.md`, `README.md`, the record and its clause file, and no other record's pins. One assembly keeps every test that reads pins through `readManifest` unchanged when pins move.
*Validity and invalidation conditions:* Applies to where clause pins live and how the tests read them. Putting pins back into one shared file, inside a record, or anywhere but beside their record requires a new owner decision.
