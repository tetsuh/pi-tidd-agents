## CL-D86 — The post-push revalidation is composed from the run's own snapshots
**Clauses:** CL-D86-map, CL-D86-builder, CL-D86-cli, CL-D86-record, CL-D86-tests

*Decision ID:* CL-D86
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#169` at its body and the owner choices https://github.com/tetsuh/pi-tidd-agents/issues/169#issuecomment-5786110213 (working session of 2026-09-23)
*Question:* The exact-autofix run on PR #149 wrote and pushed one correction and then stopped: the pre-writer `operator_revalidate` it composed by hand omitted the post-push transition the guard requires. `postPushHead` and `priorPushHeads` were optional inputs, and the map said in so many words that supplying them was a procedural obligation no check enforces. Where does the transition come from, and what does a refused post-push revalidation cost?
*Options and trade-offs:* Option A derives both from the run's own snapshots, so the parent supplies no head and the input it holds after a push is the snapshot it just took; a head beside them is refused as a second source for one fact. Option B keeps the hand-supplied heads and requires them once the run has pushed, which no check can enforce because the builder cannot know whether a run has pushed — the state that failed. Option C leaves the composition to the parent and states the rule more loudly, which is what every earlier member of this class did before it was packaged (CL-D56, CL-D68, CL-D73, CL-D81, CL-D84). On the second question, one recomposition mirrors the owner's choice on Issue #162 for a schema-invalid gate result; stopping is today's behaviour and spends a whole run on a defect in the run's own request.
*Recommendation:* Option A for both.
*Owner choice:* Option A for both (https://github.com/tetsuh/pi-tidd-agents/issues/169#issuecomment-5786110213). `build_operator_revalidate` takes `pushes`, this run's snapshots oldest first, one to five of them, and derives `postPushHead` from the last and `priorPushHeads` from the rest in order; a `postPushHead` or `priorPushHeads` beside them is refused as an input, as is a list that is empty, longer than five, not an array, not a snapshot result, or whose snapshot does not name its public head as a commit OID. Without `pushes` the builder composes the pre-push form exactly as before. A refused post-push revalidation is recomposed once from a freshly taken post-push snapshot and retried; a second refusal stops the run, and neither attempt consumes a gate or push counter. The packaged-helper alarm resets from 270,000 to 280,000 bytes on the terms CL-D73 and CL-D78 used: the measurement and the headroom are recorded at the raise — 269,652 bytes when it was chosen, leaving 10,348 — the figure is revision-qualified at `27f70ab` rather than a running total, and the per-file alarm and every authority-file guard are untouched.
*Rationale:* The guard was right and the run still ended badly, because the only thing between a correct rule and a lost run was the parent remembering what it had pushed. The map admitted as much: it named the obligation and said no check enforced it. Deriving the heads from the snapshots the run already takes removes the document the parent could get wrong, which is what the five earlier decisions in this class each concluded. Recomposing once bounds the cost of a defect that is, by construction, in the run's own request rather than in the repository: PR #149 had the correction pushed, the workspace clean, and the next batch reachable when it stopped.
*Validity and invalidation conditions:* Applies to the pre-writer revalidation in exact autofix. No grant widens: the correction batch is still one commit and one push, the writer's authority is unchanged, and the revalidation itself still refuses everything CL-D79 refuses — a chain through heads the snapshots do not name, more than five heads, or a transition that is not sole-child ancestry. A linear child someone else pushed still passes the helper if the run's snapshots name it; that residual of CL-D79 is unchanged. Taking another input, deriving the heads from anything but the run's own snapshots, or retrying a refused revalidation more than once requires a new owner decision.
