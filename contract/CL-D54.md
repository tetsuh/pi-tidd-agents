## CL-D54 — Review-only tolerates the runtime roots the harness itself writes
**Clauses:** CL-D54-review-only, CL-D54-tests

*Decision ID:* CL-D54
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#93` at its initial body
*Question:* May review-only proceed when the operator checkout contains pre-existing untracked paths under `RUNTIME_ROOTS`, or must every non-validation untracked path remain terminal?
*Options and trade-offs:* Option A extends the exact-autofix runtime-root classification to review-only's untracked-path boundary, so the harness stops blocking on its own task directories; Option B keeps the boundary as written and makes the operator relocate harness residue before every review — the residue re-accumulates with every session, and two PR #92 review runs died to it on 2026-08-30 while carrying no information about the pull request. A tolerates exactly what the stricter, mutation-bearing mode already tolerates; B pays a manual tax for a distinction no other part of the contract draws.
*Recommendation:* Option A.
*Owner choice:* Option A. This amends the CL-D38-review-only boundary sentence: a non-validation untracked path stops the run only outside `RUNTIME_ROOTS`. The roots are classified independently and no-follow, their bytes enter no fingerprint, gate payload, draft, or evidence claim, and the run never claims they were cleaned, preserved, or validated. The carve-out grants no cleanup, deletion, or relocation authority over runtime-root contents.
*Rationale:* The tolerance already existed in the other mode: exact autofix already names the same two runtime roots outside owner inventory, and the packaged helpers filter those roots out of the unexpected-untracked scan, so review-only was the only place where the harness blocked on its own task directories — an inversion, since the read-only mode was stricter than the mutating one about artifacts neither mode may read. The definition is stated in both mode references because each mode is read with the Skill alone and neither can cite the other; a fixture compares the two literals and the helper export so the sets cannot drift apart silently. This is the CL-D38 shape again: name the tolerated class precisely instead of loosening the boundary.
*Validity and invalidation conditions:* Applies to PR review-only's untracked-path boundary only. Tracked changes, index changes, ref movement, unsafe roots, and untracked paths outside `RUNTIME_ROOTS` and the frozen `VALIDATION_SANDBOX_DELTA` keep failing closed, and the workspace-side rejection of runtime-root paths is unchanged. If the two mode references ever name different root sets, or the helpers stop filtering the same roots, the drift fixture invalidates this record. Widening the root set requires a new owner decision.
