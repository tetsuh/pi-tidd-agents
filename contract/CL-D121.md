## CL-D121 — The Issue root runs no convergence stage
**Clauses:** CL-D121-record, CL-D121-schema, CL-D121-skill, CL-D121-contract

*Decision ID:* CL-D121
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#304`, step 2a of #190, with the owner's step-2 decisions (https://github.com/tetsuh/pi-tidd-agents/issues/190#issuecomment-6243884276)
*Question:* CL-D62 runs a non-authoritative convergence stage before the adversarial gate on both roots. On the Issue root it costs about as much time as a formal gate, while an Issue is a specification draft whose review the owner wants kept lighter than a pull request's. Should the Issue root keep the stage?
*Options and trade-offs:* Keeping the stage on both roots changes nothing, but every Issue round pays for a preliminary review whose findings Sol reviews again. An operator can already skip it per run with a disabled role, but that is configuration rather than the Issue default. Dropping it on the Issue root saves that cost on every Issue round and leaves Sol as the first gate there, as it was before CL-D62.
*Recommendation:* Drop the stage on the Issue root only.
*Owner choice:* The Issue root runs no convergence stage. Its order is Sol, then Terra, on the legacy route and on the CL-D31 and CL-D32 candidate routes alike. A version 2 envelope or expectation naming the `convergence` gate on the Issue root is outside its root and fails closed, and `tidd-convergence-reviewer` declares the pull-request schema. The pull-request root keeps the stage, its caps and its order unchanged. This widens CL-D1's freeze on `agents/` for one line of `agents/tidd-convergence-reviewer.md`, whose body named the decision-drift gate among those after it. The two phrases CL-D62 retired for a Sol-first order are current again in the Issue Skill only, where `test/records/workflow-vocabulary.json` allows them by this decision.
*Rationale:* The Issue review's cost is mostly its gates, and the convergence stage is the one gate there that holds no authority. Removing it is a narrowing: it adds no gate, mode, verdict or authority, and every formal gate keeps its budget and order relative to the other.
*Validity and invalidation conditions:* Applies to the Issue root's gate order, preflight and status block, to the shared convergence section and the README, to the gate result validator's Issue gates, and to `tidd-convergence-reviewer`'s declared schema and gate sentence. It changes no pull-request behaviour: the convergence role's declared schema narrows from the union back to the pull-request schema, which every pull-request result already matched. Running a preliminary stage on the Issue root again requires a new owner decision.
