## CL-D107 — A gate result whose correlation names no run is relaunched once
**Clauses:** CL-D107-record, CL-D107-driver, CL-D107-tests, CL-D107-forward-d93, CL-D107-review-only, CL-D107-forward-d51, CL-D107-autofix, CL-D107-autofix-driver, CL-D107-addendum, CL-D107-forward-d96, CL-D107-gate-contract, CL-D107-forward-d58

*Decision ID:* CL-D107
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#254` at its body, and the owner decisions on it (https://github.com/tetsuh/pi-tidd-agents/issues/254#issuecomment-6040793987, and for exact autofix https://github.com/tetsuh/pi-tidd-agents/issues/254#issuecomment-6041458658)
*Question:* In round 2 of PR #253 the parent changed one path in a gate launch's task. The gate's verification failed, and the gate still returned a placeholder envelope whose correlation names no run: every OID and digest is the null value. `gate_result_read` refused it as `correlation_mismatch`, and the round ended BLOCKED with no gate run. Should such a result stop the round?
*Options and trade-offs:* Option A has the driver detect a mistranscribed launch, but the only record of the task as sent is the runner's log. Option B shortens the pointer, which makes a copy fault less likely but does not handle one. Option C treats a result that names no run as no result of the launch, so the relaunch an absent output gets applies to it.
*Recommendation:* Option C.
*Owner choice:* Option C, in both drivers. A designated output whose correlation has `baseOid` and `headOid` both 40 zeros and `contractInput` and `snapshotFingerprint` both 64 zeros names no run. The review-only driver relaunches it once with the same request and no round spent, as CL-D93 relaunches a malformed result, and the stop reason after a second one keeps the code `correlation_mismatch`. Exact autofix relaunches it within CL-D51's budget: once per run, never after the writer has launched, after the target is rechecked. A correlation that names any real value, another run's result included, stays a refusal at once.
*Rationale:* The null OID is no commit and the zero digests are no content, so such a correlation describes no run that could be stale, misattributed or contradicted. A relaunch replaces it with the same prevalidated launch and conflicts with nothing it held.
*Validity and invalidation conditions:* Applies to both drivers. In exact autofix it is the one widening of CL-D51's terminal rule for a designated output byte; any other output stays terminal there. A second relaunch, a larger budget, or a weaker test than all four null values requires a new owner decision.
