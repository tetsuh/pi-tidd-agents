## CL-D61 — The manifest requests are built and the required-evidence set is checked before any gate
**Clauses:** CL-D61-map, CL-D61-shared, CL-D61-tests

*Decision ID:* CL-D61
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#105` at its body, the owner scope decision https://github.com/tetsuh/pi-tidd-agents/issues/105#issuecomment-5525979290, and the implementation note https://github.com/tetsuh/pi-tidd-agents/issues/105#issuecomment-5532551686
*Question:* After CL-D56, the parent still assembled three documents by hand: the `manifest_compare` capture request at `AFTER_STAGING`, its compare request at `BEFORE_COMMIT`, and the required-evidence set that `build_gate_expectation` accepts on shape alone. PR #103's exact-autofix run stopped terminally on a capture request carrying both mode fields, and PR #104 spent Terra's only retry on a required-evidence entry naming a file the repository does not have. How do these become unrepresentable or caught before a gate runs?
*Options and trade-offs:* Option A adds `build_manifest_capture` (from the frozen overlay) and `build_manifest_compare` (from the capture), pure like the CL-D56 family, and a separate read-only `required_evidence_check` that verifies every `file`-kind entry exists before the expectation is built. Option B folds the existence check into `build_gate_expectation`, which breaks CL-D56's purity rule and makes one builder reach the filesystem. Option C leaves the manifest requests hand-assembled and documents the mutual exclusion more loudly, which is the state that already killed a run.
*Recommendation:* Option A.
*Owner choice:* Option A. `build_manifest_capture` takes `overlay` (data of `overlay_freeze`) and `cwd` and emits `{ cwd, parent, authorizedPaths }`; `build_manifest_compare` takes `captured` (data of `manifest_compare`) and `cwd` and emits `{ cwd, parent, manifest }`; each derives `parent` from its producing operation and cannot emit the other mode's field, and each validates its output through the boundary's own predicate table; `build_manifest_capture` also applies the consumer's authorized-path rules, held as one pure predicate in the composition module and shared with the guards, so an empty, duplicate, non-normalized, repository-metadata, or runtime-root set fails at build naming the consumer's subcheck. `required_evidence_check` takes `cwd` and `requiredEvidence`, runs the boundary's own shape check, and requires every `file`-kind `source` (absolute, or relative to `cwd`) to be an existing regular file; the first missing entry fails with `invalid_request`, subcheck `required_evidence_presence`, naming the source. Other kinds are not existence-checked. This decision widens CL-D56's builder family from five to seven; the CL-D44 declared-field set is unchanged because both builders reuse `data:overlay_freeze` and `data:manifest_compare`.
*Rationale:* Both failures were hand-assembly errors at boundaries where a request-shape defect is terminal or spends the only retry, while every writer correction and every gate verdict involved was correct. Deriving the parent and the authorized set from the overlay that froze them, and the compare parent from the capture, follows CL-D47: a hand-copied duplicate of a derivable value can only ever be wrong. The existence check stays out of the builders so CL-D56's purity rule keeps holding; it is a read-only observation whose failure names its subcheck and observed value (CL-D55), placed before `build_gate_expectation` so a nonexistent required file never reaches a gate as an omitted attestation.
*Validity and invalidation conditions:* Applies to exact PR autofix's `AFTER_STAGING` and `BEFORE_COMMIT` request assembly and to required-evidence assembly on every route that builds a gate expectation. It changes no guard predicate, no CL-D39 consequence, no gate order, and no authority; `manifest_compare` revalidates every built request as before. Adding a builder, widening one's inputs, or existence-checking another evidence kind requires a new owner decision.
