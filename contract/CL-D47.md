## CL-D47 — The fresh-finding namespace is derived, never supplied
**Clauses:** CL-D47-shared, CL-D47-tests

*Decision ID:* CL-D47
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#79` at its initial body and the owner's live instruction `go ahead`
*Question:* Should the parent keep supplying `freshFindingIdPrefix` to `gate_result_validate`, when the validator derives the same value from the correlation and only checks that the copy matches?
*Options and trade-offs:* Keeping the field preserves the wire shape but preserves the defect with it: a hand-copied duplicate of a derivable value can only ever be wrong, and it carries no verification power the correlation did not already carry. Accepting it silently would hide drift in stale orchestrations. Deriving unconditionally and rejecting any supplied copy removes the failure class and tells a stale caller exactly what changed.
*Recommendation:* Derive unconditionally; reject a supplied copy, right or wrong alike, with a message naming the change.
*Owner choice:* As recommended. The validator computes the namespace from the gate and target number alone; an expected input carrying `freshFindingIdPrefix` fails closed as `invalid_request: freshFindingIdPrefix is derived from the correlation; do not supply it`. Fresh findings still bind to the derived namespace exactly as before, and the shared contract sentence now reads that the namespace is derived from the gate and the target number, never supplied — which was already true of both workflow roots, so the shared edit records reality rather than changing it.
*Rationale:* Observed on `tetsuh/sitometron` autofix runs: 43 logged `prefix mismatch` losses, including a Terra invocation whose orchestrator computed the prefix from the result's empty findings and a run that discarded a completed Sol `MERGE` over `TER-45-` versus `TERRA-45-`. Every loss was a whole non-resumable run, and none reflected anything about the target. The suffix-grammar clause the old sentence carried (`[A-Z0-9._-]+`) governed a value the parent no longer writes; fresh finding IDs remain constrained by the validator's own finding-ID checks. The shared prose shrinks by this change, so no authority budget is consumed.
*Validity and invalidation conditions:* Applies to `gate_result_validate` and the shared invocation-contract sentence. Fresh-finding namespace enforcement is unchanged in strength; only its source moved from a supplied copy to the derivation that always governed. Reintroducing a caller-supplied namespace, or accepting one silently, requires a new owner decision.
