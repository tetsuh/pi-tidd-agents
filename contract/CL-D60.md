## CL-D60 — Gate identities name workflow functions; schema version 2
**Clauses:** CL-D60-identities, CL-D60-tests

*Decision ID:* CL-D60
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#100` at the PR 2 design comment https://github.com/tetsuh/pi-tidd-agents/issues/100#issuecomment-5514320009 and the owner decisions https://github.com/tetsuh/pi-tidd-agents/issues/100#issuecomment-5509800274 and https://github.com/tetsuh/pi-tidd-agents/issues/100#issuecomment-5526064661
*Question:* CL-D59 moved agent identities to workflow roles, but the structured envelope still records each gate as `sol` or `terra` and derives fresh-finding namespaces `SOL-` and `TERRA-`, so durable gate records keep naming model families. How do gate identities become workflow functions without reinterpreting valid version 1 evidence?
*Options and trade-offs:* Option A adds envelope schema version 2 with gate identities `adversarial`, `decision-drift`, and `safety`, validates each against the root that runs it, derives `ADV-`, `DRIFT-`, and `SAFETY-`, and keeps version 1 accepted for one release by an explicit version branch with no cross-mapping; prose keeps Sol and Terra as gate nicknames, the authority ceiling is raised once for the paragraph this needs, and the publication marker parses both vocabularies for the release. Option B rewrites version 1 in place, which reinterprets stored evidence and breaks every recorded fixture. Option C renames the prose vocabulary in the same change, which touches about ninety sites and couples a cosmetic rename to a validator change.
*Recommendation:* Option A.
*Owner choice:* Option A, with the three sub-decisions recorded on the Issue: prose keeps the Sol and Terra nicknames; the ceiling takes a reviewed raise rather than trimming existing authority; the marker keeps `sol`, `terra`, and `sol+terra` parseable beside the version 2 gates for the same release. The seven authority files move from 128,000 to 140,000 bytes; they measured 128,618 bytes on this change, and the raise leaves 11,382 bytes, asserted at the raise as CL-D48 requires and never against later growth. The fresh-finding prefixes are `ADV-`, `DRIFT-`, and `SAFETY-`, derived from the gate exactly as CL-D47 derives them today. The packaged expectation builder ships version 2 only.
*Rationale:* A gate record is durable evidence; naming a model family in it makes every model replacement look like a change of what was reviewed. The version branch is explicit so that a version 1 envelope is checked against version 1 and nothing else: a version 2 gate inside a version 1 envelope, or the reverse, is an unknown enum, and a fresh finding under the other version's namespace is a record error, so no valid version 1 evidence is reinterpreted and no cross-mapping exists to be wrong. The root check is new and tightening only: version 1 never tied `terra` to a root, and version 2 rejects `decision-drift` on the PR root and `safety` on the Issue root. Sol and Terra remain nicknames in prose because the record, not the prose, is what a model retirement must not touch; the prose rename can follow when the window closes. The raise follows CL-D43 and CL-D48: 146 bytes of nominal headroom could not hold the shared paragraph, trimming existing authority would have made an unrelated semantic edit a precondition of this change, and the raise-time property is asserted against the measurement recorded here.
*Validity and invalidation conditions:* Applies to `gate_result_validate`, `build_gate_expectation`, the composition table, the publication marker, and the shared transport prose. It changes no verdict vocabulary, gate order, round budget, confirmation duty, or record ownership. The version 1 branch, its fixtures, and the marker's version 1 gates expire together in the release after this one by a recorded decision; adding a gate identity, a third version, or any cross-mapping requires a new owner decision, as does the next ceiling raise. CL-D62 later added the `convergence` identity under its own decision.
