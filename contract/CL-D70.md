## CL-D70 — The declared envelope field accepts the producer payload
**Clauses:** CL-D70-map, CL-D70-record, CL-D70-tests

*Decision ID:* CL-D70
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#111` at PR #123 head `3d27e8487a984dd323ebfb2fbbbced506b3d7e5d`, the options comment https://github.com/tetsuh/pi-tidd-agents/issues/111#issuecomment-5642144463, and the owner choice https://github.com/tetsuh/pi-tidd-agents/issues/111#issuecomment-5642229512
*Question:* A `/tidd-pr 123` run stopped before every gate because the parent passed the `operator_capture` payload where `build_operator_revalidate` declares the whole envelope, and the same parent had passed the envelope correctly at an earlier boundary of that run. Nine cross-operation fields are declared; eight take the producer's payload and `operator_revalidate.captured` alone takes the envelope, while two invocation-map rows carry a field named `captured` whose forms differ. What should the field accept?
*Options and trade-offs:* Option A accepts the envelope or the payload and normalizes the payload to the envelope, so the exception disappears. Option B keeps the strict shape and improves only the rejection message, which documents the class without removing it: a rejected request stops the run at that phase with no retry. Option C renames the field, which removes the ambiguity by naming but changes the wire for every caller and turns a stale caller's request into an unknown field.
*Recommendation:* Option A.
*Owner choice:* Option A. A value matching the producer key set exactly is wrapped as its envelope in `normalizeDeclaredInputs`, normalized to the envelope before any check, so one canonical form reaches the consumer and a builder emits one form. The payload predicate recognizes `operator_capture` output by that key set, exported beside the producer rather than retyped, so the `tetsuh/sitos#165` reproducer stays rejected: a partial or hand-built object is not producer output, a failed capture carries no payload, and another operation's payload matches another key set. A rejection now also names what would have been accepted.
*Rationale:* This is the CL-D47 shape once more: a caller choosing between two forms of one value it already holds can only get it wrong, and the wrong choice costs a whole run before any gate, which is what CL-D68 packaged the launch and read paths to stop. Accepting the payload removes the choice instead of documenting it, and the exact key set keeps the cross-operation substitution CL-D44 exists to catch.
*Validity and invalidation conditions:* Applies to the declared fields whose shape is an envelope, which is `operator_revalidate.captured` alone (CL-D89 later declared `commit_create.captured` and `push_publish.captured` the same way), and to the builder and CLI paths that carry it. It adds no operation, no authority, and no retry, and changes no verdict rule. Accepting a payload that is not the producer key set exactly, or normalizing any other declared shape, requires a new owner decision.
