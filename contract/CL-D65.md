## CL-D65 — Gate children carry the envelope duties and validate their own envelope
**Clauses:** CL-D65-payload, CL-D65-record, CL-D65-tests

*Decision ID:* CL-D65
*Kind:* contract
*Target and revision:* `tetsuh/pi-tidd-agents#117` at its body, https://github.com/tetsuh/pi-tidd-agents/issues/117, and the owner's instruction to proceed (working session, 2026-09-07)
*Question:* Gate children keep returning envelopes that pass the runner's JSON-schema check and fail the packaged semantic validator — Terra on #104, Sol twice on #109, convergence four times on #113 — and each failure costs the route's only retry. The schema cannot express the rules the validator enforces. Where should those rules reach the child?
*Options and trade-offs:* Option A states the three envelope duties in the Every-gate invariant payload block, has the parent name the host-trusted packaged CLI path and the expectation file, and has every reviewer body run `gate_result_validate` on its draft before submitting. Option B relaxes the validator or adds a repair step, which moves verdict authority toward an unvalidated document and is declined. Option C raises the children's thinking level, which does not teach them a rule they cannot see.
*Recommendation:* Option A.
*Owner choice:* Option A. The Every-gate block carries the duties: every parent-assigned finding appears in `findings` with `origin: assigned`, its exact tuple, and exactly one confirmation; a fresh finding carries no `blockerKey`; an adversarial result links a `findingId` only for a counterexample or unavailable-evidence outcome, and only to an id present in `findings`; and the child submits only an envelope `gate_result_validate` accepted against the supplied expectation. This decision widens the CL-D1 `agents/` freeze exactly once more, for one sentence in each of the four reviewer bodies; the writer body is unchanged because it returns no gate envelope.
*Rationale:* Every reviewer child has `bash` and the validator is read-only, so the check the parent runs after the fact can run inside the child before it submits, where a rejection costs one more turn instead of a retry or a run. The duties are stated where every gate invocation already copies them verbatim (CL-D2), and the agent sentence keeps the duty alive when a payload omits it. The gate-side complement of #111's parent-side builders.
*Validity and invalidation conditions:* Applies to the Every-gate payload block and the four reviewer bodies; the validator, the schema, and every route's retry rule are unchanged, and a child that submits a rejected envelope is handled exactly as before. Relaxing the validator, adding a repair step, or letting the child's own run substitute for the parent's `gate_result_validate` requires a new owner decision.
